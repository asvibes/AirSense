## Active application architecture

The zero-byte files above are placeholders; the current app does not import or render them. The requested core behavior is implemented on other active surfaces:

- `app/routers/alerts.py` renders `app/templates/alerts.html`, which is the authenticated dashboard shell and contains the overview, rooms, sensors, alerts, history, thresholds, members, activity, and demo views.
- `app/static/js/dashboard.js` is loaded by that page. It handles dashboard polling, history charts and heatmap rendering, room and sensor interactions, and demo actions. The empty `polling.js` and `heatmap.js` files are not loaded.
- Registered JSON blueprints provide the room, sensor, history, threshold, and dashboard APIs. `app/routers/demo.py` handles simulator readings and the DALTON multipart CSV/TXT upload and replay through the existing ingestion pipeline. `app/routers/uploads.py` is not registered, and adding a duplicate upload endpoint is not required for DALTON replay.
- The test suite uses `tests/helpers.py` and `unittest.TestCase`-based tests, which pytest discovers directly. No pytest fixtures are currently required from `tests/conftest.py`.

The API and application tests cover these active paths. Do not populate the empty templates, scripts, or router solely to make the inventory non-empty; first add a product requirement and wire a single implementation into the active route/page.

## Refreshing this inventory

Run this PowerShell command from the repository root to list tracked zero-byte files:

```powershell
git ls-files | ForEach-Object {
    if ((Test-Path -LiteralPath $_ -PathType Leaf) -and
        (Get-Item -LiteralPath $_).Length -eq 0) {
        $_
    }
}
```

Update the count and path lists above from the command output after adding/removing files, filling a placeholder, or merging another branch. This report is a checked-in snapshot, not an automatically generated inventory.
